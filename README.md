# 潜水作业排班与安全复核台（离线单页应用）

在原有“水下考古潜水记录”单页上扩展：遗址、潜次任务、潜水员、气瓶余量、天气窗口五要素联合决定任务能否安排；
任务按 **待复核 → 已批准 → 执行中 → 已关闭**（另可驳回）流转；同人时间冲突、气量不足、恶劣天气一律拦住；
重复提交幂等、越级变更拒绝；每次修改记录操作者、时间与前后状态；任何失败都不留下部分数据。
原有的标记地图、筛选、潜次时间线、JSON 导出全部保留并纳入同一套审计与事务。

零运行时依赖、零网络请求，可直接双击 `index.html` 使用，数据只存在本机浏览器。

## 目录结构

```
index.html            页面（看板 / 基础数据 / 标记图 / 操作记录 四个标签页）
css/app.css           样式（桌面 5 列看板，≤720px 手机单列）
js/store.js           数据层（纯逻辑、UMD，浏览器 <script> 与 Node require 通用）
js/app.js             界面层（渲染与事件，不含业务规则）
sw.js                 Service Worker：http 访问后断网仍可打开外壳
manifest.webmanifest  PWA 清单
tools/serve.js        零依赖静态服务器（npm start）
test/store.test.js    数据层自动化测试（node:test，35 项）
test/e2e/verify.js    真实浏览器端到端验证（Playwright + Chromium，21 项）
test/e2e/shots/       浏览器验证截图
```

数据层与界面分离：`js/store.js` 不知道 DOM 的存在，可在 Node 中独立测试/复用；`js/app.js` 只读写 Store，
不自行判断冲突或状态。

## 运行

无需安装、无需构建，两种方式任选：

1. **直接打开**：双击 `index.html`（`file://` 即完全离线，业务数据存 localStorage）。
2. **本地服务器**（可验证 Service Worker 离线缓存）：
   ```bash
   npm start          # http://localhost:8080
   ```

使用前先在右上角填写“当前操作者”姓名（记在本机）；任何写操作都要求操作者，匿名变更一律拒绝。

## 业务规则（数据层强制，界面只是呈现）

- **排班五要素**：任务必须选定遗址、起止时间、水深、水下时长、≥1 名潜水员且每人分配一个气瓶。
- **同人时间冲突**：同一潜水员与任意活动潜次（待复核/已批准/执行中）时间重叠 → 拒绝，提示冲突潜次。
- **气瓶时间冲突**：同一气瓶同时段分给两个潜次 → 拒绝；同潜次内人员或气瓶重复 → 拒绝。
- **气瓶余量**：计划气量 = SAC × 时长 × (1+水深/10) × 1.2 安全余量；
  气瓶可用气量 = 水容积 × (当前表压 − 残压保护)，须同时覆盖本任务与其它活动任务的累计占用，否则拒绝。
  表单实时显示每人计划气量与是否充足。
- **天气窗口**：任务时间区间必须完全落在该遗址“良好”窗口并集内；与任何“恶劣”窗口相交即拒绝。
- **状态机**（只允许以下迁移，其余全部 `ILLEGAL_TRANSITION`）：
  - 待复核 → 批准 → 开始执行 → 关闭（正常/异常，异常必须写情况说明，关闭必须填实际分钟数）
  - 待复核/已批准 → 驳回（必须填原因）
  - 只有待复核任务可编辑/删除；批准与开始执行前会**重新复核**全部硬规则（防止基础数据变化后带病放行）
  - 关闭时按实际耗气扣减气瓶表压，扣到残压保护以下则拒绝关闭，需先到“气瓶”页登记补气
- **重复提交**：前端每次提交带 `clientKey`，同一键重复提交返回首次任务，不重复落库、不重复记审计。
- **审计**：创建/修改/删除/批准/驳回/开始/关闭均记录操作者、毫秒时间戳、动作、变更前后完整快照；
  “操作记录”页可按对象筛选并展开前后 JSON。
- **原子性**：所有写操作先在深拷贝草稿上完成全部校验，成功后**仅一次** `localStorage.setItem`；
  校验失败不写盘（已在测试中通过“写盘次数计数”验证），`setItem` 抛错（配额等）时内存状态也回滚。
- **兼容**：旧版 `zfl30Marks` 标记数据首次打开自动迁移到新库；旧版“导出标记 JSON”按钮保留。

## 验证结果（2026-09-12，本机实际执行）

- 数据层自动化测试：**35 / 35 通过**（Node v20.20.2，`node:test`）。
- 真实浏览器验证：**21 / 21 通过**（Playwright 1.63.0，Chromium 153.0.8010.12，headless，ARM64 Linux）。
  桌面 14 项、手机 5 项、离线/file 直开 2 项，全部通过，过程中页面控制台无 JS 错误。
- 桌面截图：`01-desktop-board`（看板）、`02-desktop-map`（标记图/筛选/时间线/导出）、`03-desktop-audit`（操作记录）。
- 手机截图：`04-mobile-board`（单列看板）、`05-mobile-data`（手机端补气）。
- 离线截图：`06-offline`（Service Worker 缓存外壳后断网刷新，仍完成“驳回”并落库）。
- 浏览器实测走通的关键流程：
  合法排班进入待复核；同人与 DIVE-001 时段重叠被拦；在恶劣窗口（雷暴）内排班被拦；
  批准→执行→关闭后气瓶按实耗扣压（18m×30min，220→94 bar）；已关闭卡片无任何越级按钮；
  驳回必须填原因（空原因 HTML/数据层双拦截）；重复 `clientKey` 只产生一条；
  标记新增、类型筛选、时间线、标记 JSON 与全量 JSON（含审计）导出；
  手机端新增排班、驳回、异常关闭（填说明）、登记补气；
  断网后刷新页面仍可用并完成驳回；`file://` 双击直开可批准。

浏览器验证过程中实际发现并修复了两个界面缺陷（均已被验证脚本回归覆盖）：

1. 弹层 `.modal-backdrop` 的 `display:grid` 覆盖了 `[hidden]` 默认隐藏，关闭后仍全屏拦截点击
   → 增加全局 `[hidden]{display:none!important}`。
2. 操作者输入框 `change`（恰在点击按钮的 pointerdown 时触发失焦）后全量重渲染，替换了被点击的按钮节点，
   导致第一次点击落空（pointerup 落在新节点、浏览器不派发 click）→ 该监听只持久化、不再重渲染。

## 数据存储与重置

所有数据存于浏览器 `localStorage` 键 `zfl30.db.v1`（旧键 `zfl30Marks` 只读迁移）。
清除站点数据即恢复示例种子。导出全部数据可用于备份/交接，导出文件含版本号、导出时间与完整审计。

## 说明与取舍

- 气量模型为现场简化模型（常压 1+深度/10 ATA、固定 SAC、20% 余量、关闭按实际分钟数线性扣瓶），
  阈值与常量集中在 `js/store.js` 顶部（`DEFAULT_SAC`、`GAS_MARGIN`、`DEFAULT_RESERVE_BAR`），便于按潜水手册调整。
- 活动任务（含待复核）按计划气量保守占用气瓶；关闭扣瓶后如需复用同瓶，先在“气瓶”页登记补气。
- Service Worker 仅在 http(s) 下注册；直接用 `file://` 打开时页面本身即离线，无需缓存。
